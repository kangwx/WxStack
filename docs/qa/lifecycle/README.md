# 浏览器生命周期回归

本目录记录真实 Chrome/Cocos 运行结果。测试使用独立的临时浏览器配置、1920×1080 视口、DPR 1，以及本地临时复活服务；没有读取个人浏览器配置或改写游戏的 phase、分数、方块位置。导航、暂停、重开和返回均调用当前游戏的业务命令。测试模式通过现有命令开启，因此批量重开不消耗体力。

执行脚本：[tools/browser-lifecycle.cjs](../../../tools/browser-lifecycle.cjs)。默认目标为 `http://127.0.0.1:7458/?profile`，可用 `WXSTACK_TEST_URL` 指定另一份已构建的 Debug 页面。运行需要可用的 Chrome、Playwright 和本地网络监听权限。

## 覆盖范围

- 先预热一次完整页面往返及暂停重开路径，然后执行 50 次设置 → 昵称 → 设置 → 首页 → 排行榜 → 首页循环。逐次核对路由、返回焦点和转场解锁状态。
- 执行 50 次暂停后重开，每次重新返回首页。比较场景节点、组件、Cocos 输入/视口/应用监听、定时器、3D 池和体力。
- 转场期间改变视口再恢复；禁用游戏组件 400 ms 后重新启用，检查坐标冻结、物理开关、监听解绑及恢复。
- 关闭测试模式，等待移动方块自然越过支撑边缘后落下失败；通过真实复活 API 连续打开和关闭三次二维码。每次等待一次轮询，检查同一纹理复用，关闭后 SpriteFrame、Texture 和图像引用清空，轮询定时器停止。另检查创建请求未返回时立即关闭。

二维码身份使用测试侧 WeakMap 标识同一个真实资源对象，同时保存资源公开的 uuid；WeakMap 不保留资源强引用。测试不通过改写资源 ID 模拟复用。该项验证资源拥有关系和释放命令，不代替 GPU 内存分析或手机扫码验收。

## 内存与统计方法

每个样本都在首页稳定后等待 600 ms，连续执行两次 CDP `HeapProfiler.collectGarbage`，再读取 `Runtime.getHeapUsage`、`Memory.getDOMCounters` 和当前 Cocos 场景。GC 成功或不支持的结果原样记录。数据包含引擎、调试代码、浏览器和测试查询产生的开销；单组前后差值不能证明没有泄漏，需要结合对象数量及长期趋势判断。

`first-loop-run.json` 保留首轮数据：50 次导航、50 次重开、视口切换和禁用恢复已经完成；随后测试错误地把 Cocos Asset 的 `_id` 当作资源身份，在首个二维码断言处停止。该失败属于测试仪器，不能将这份文件当作完整 QR 验收。修正后的完整结果写入 `browser-lifecycle.json`。所有浏览器错误和失败请求均保留，不通过过滤异常制造绿色结果。

这些结果来自 macOS / Apple M1 Pro 的 Chrome Debug 构建。Android 投影设备 1080p、60 fps 和发布版性能仍为 **未验证**。
