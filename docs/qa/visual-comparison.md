# UI 重构首轮视觉对照

2026-09-14 19:12（Asia/Shanghai）逐张检查旧版截图与新版 19:09 的截图。两侧均为 Chrome 152.0.7977.83、1920×1080、DPR 1；旧版为独立构建，18 个快照源码/场景文件构建前后哈希一致。

**页面位置、标题字形和主要配色基本保持；当前仍有背景形状与描边回归，尚不能按视觉等价验收。** 本轮没有修改代码，也不把图片差异解释为性能结论。

新版待比较图片已冻结在 `comparison-initial`，防止根任务重拍 `current` 后证据被覆盖；原始截图哈希、采样坐标和颜色见 [measurements.json](comparison-initial/measurements.json)。坐标均以截图左上角为原点，单位为像素。

## 优先修复项

1. **P1：恢复排行榜内容底板的圆角矩形覆盖。** 旧版范围约 `(514,248)` 到 `(1407,935)`；新版在相同范围内呈椭圆。采样 `(535,350)` 和 `(1390,910)`，旧版 RGB 为 `247,237,220`，新版变为外面板的 `255,248,231`；中心 `(960,700)` 两侧仍为 `247,237,220`。这证明主要是形状覆盖错误，而不是整个主题色改变。
2. **P2：恢复首页预览底板和领奖台几何。** “查看完整榜单”底板约 `(1506,430)` 到 `(1824,470)`；旧版保持平直上下边和小圆角，新版横向拉伸为椭圆。采样 `(1525,435)` 从浅绿 `220,235,222` 变为面板色 `255,248,231`。三个领奖台约位于 `x1598–1733 / y213–270`，新版端部过圆，原方块语义减弱。
3. **P2：统一回原按钮焦点和普通描边。** 首页开始按钮 `x400` 处的顶部深色像素，旧版只有 `y558`，新版为 `y557–559`；设置焦点顶部由 `y367–368` 变成 `y366–368`。普通按钮及统计卡边界也更显眼，例如首页统计卡 `(200,411)` 从 `244,237,221` 变为 `230,224,209`。应检查焦点 PNG 的有效线宽、九宫格边界与重复启用的 border/focus 层。
4. **P2：恢复排行榜装饰笔画。** 关闭 X 约在 `(1355,140)` 到 `(1385,170)`，新版笔画明显更粗；副标题左侧短横约 `(519,225)` 到 `(574,233)`，新版是平头矩形，旧版为圆头。使用已有绘制几何作为参考，不更改字号或标题位置。

上述形状差异与 SIMPLE 拉伸圆形/圆角图样、九宫格边界或图层叠加不一致相符，属于待代码核实的原因推断。本报告仅根据实际截图确认结果，不替代资产或实现审查。

## 配色、字重和位置复核

- 首页主面板 `(100,500)` 两侧均为 `255,248,231`；开始按钮内部 `(400,580)` 两侧均为 `173,206,196`；统计卡内部 `(200,430)` 两侧均为 `243,236,220`。主要填充色没有漂移。
- 四个主标题区域执行原始 RGB 对照，均为 **0 个变化像素**：首页 `(200,195,410,120)`、设置 `(230,215,360,80)`、昵称 `(860,375,215,50)`、排行榜 `(510,110,235,80)`，格式为 `x,y,width,height`。这些区域的字重、字号和定位没有发生变化。
- 四页均未发现主文字缺失、意外隐藏或面板整体错位。首页、设置和昵称后方的静态大塔与展台边缘保持对应；排行榜对场景的遮挡位置也一致。
- 新版 `current/browser-smoke.json` 报告 `errors: []`。旧版浏览器无 pageerror，但保留了 favicon 404 和一次旧版 renderable-component 警告；这些日志不是本轮观察到的背景变形原因。

## 修正后复核

重新采集相同四页、相同尺寸与 DPR，优先比较排行榜矩形四角、首页预览底板、三个领奖台、焦点顶部和普通按钮轮廓。保留本报告的冻结截图作为修正前证据。随后继续检查非空榜单、其他焦点状态、二维码、手机尺寸和精确转场；本轮结果不覆盖这些尚未逐项对照的状态。
